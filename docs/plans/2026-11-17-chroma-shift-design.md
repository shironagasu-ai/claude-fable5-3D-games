# Chroma Shift — 色ずれパズル 設計メモ

8作目。テーマは「色彩」。固定条件は「レトロなドット絵調」と「ポストエフェクトをしっかりかけられる構成」。

## 企画の経緯

- 却下: 色を塗り戻すアクション（既存の有名作に近すぎる）、色レンズ（既存の 2D 作品と仕組みが同じ）
- 候補: G 色ずれ / H 顔料の流体 / I パレット書き換え → **G を採用**
- 採用理由: 色収差というポストエフェクトそのものが遊びの中核になる。R+G+B=白 が画面を見るだけで分かる

## 規則

- 色は 3 ビット（赤=1, 緑=2, 青=4）。盤面は R・G・B の 3 層で、各層を独立に 1 マス単位でずらせる
- 3 層が重なった白(7)のマスだけ歩ける
- 層をずらせるのは、ずらした後も自分の足元が白のままのときだけ（落下はない）
- 各層は元の位置から縦横それぞれ M マス（現在 2）まで。ステージごとに動かせる層を限定できる
- ◆クリスタル: そのマスがちょうど指定色（Y/M/C）になった瞬間に点灯し、以後は消えない。全点灯で出口が開く
- 評価はずらし回数。PAR = ソルバーが求めた最小ずらし回数

## 技術構成

- 1 ファイル（`games/chroma-shift/index.html`）。Three.js はフルスクリーン四角形のシェーダー描画にのみ使用
- 描画パイプライン:
  1. 256×192 のレンダーターゲットに盤面を描く。層ごとにマスクテクスチャ（R/G/B チャンネル）を
     オフセット付きで参照して加算。層ごとに固有のドット模様（赤=斜線 / 緑=点 / 青=横線）で色覚に頼らず読める
  2. スプライト・文字（3×5 ドットフォント）は 256×192 の 2D キャンバスに描いて同じパスで重ねる
  3. 半解像度で明部抽出＋分離ガウスブラー（ブルーム）
  4. 最終パス: 画面湾曲、色収差（ずらした方向に一瞬強くかかる）、走査線、RGB マスク、ビネット、ノイズ
  5. 低解像度パスで 8 色ディザ（Bayer 4×4）も選べる
- 拡大はドットの輪郭を保つ補間（整数倍でない拡大でも縞が出ない）
- エフェクトは FX パネルで個別に切替、CRT / SOFT / RAW のプリセット。設定は localStorage に保存
- 規則は `/*CORE-BEGIN*/` 〜 `/*CORE-END*/` の純関数にまとめ、テストと生成ツールから同じコードを読む

## ソルバーとステージ

- 状態 = (プレイヤー位置, 6 個のオフセット, 点灯済みクリスタル)。歩きはコスト 0、ずらしはコスト 1 の
  0-1 幅優先探索で、ずらし回数が最小の手順を求める
- 用途: HINT（次の一手を表示）、ステージ生成、E2E での全面解答チェック
- ステージは `tools/chroma-shift-gen.mjs` でランダム生成 → ソルバーで手数を測り、狙いの範囲のものを採用
- 現在 9 面（PAR 2, 5, 6, 6, 9, 10, 11, 13, 14）。10 面目（PAR 15 以上）は生成時間内に見つからなかった

## 検証（E2E: `npm run test:chroma-shift`）

- 全面: 開始地点が白・ソルバーで解ける・最小手数が PAR と一致
- ブラウザで全 9 面をキー入力だけで通しクリア → タイトルへ戻る・進行が保存される
- UNDO / HINT / 足元が崩れるずらしの拒否 / 固定層
- スマホ縦画面（390×844）でボタン操作だけでクリア、操作盤が画面内に収まる
- スクリーンショット: `tests/output/chroma-*.png`（CRT / RAW / ディザ / スマホ）

## 今後の候補

- 手作りの面を足す（生成面は解けるが、意図のある「ひらめき」は少ない）
- 2 層の重なり（黄・シアン・マゼンタ）に別の役割を持たせる床（例: 黄の床は赤レンズ…ではなく、黄は滑る など）
- 層の可動範囲 M を面ごとに変える
